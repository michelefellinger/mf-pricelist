# MF PriceList v1 – Entscheidungen und Prüfstand

Tracking: [MIC-56](https://linear.app/michele-fellinger/issue/MIC-56). Implementierung ausschließlich auf `feature/mf-pricelist-v1`. Repository war beim Start leer; kein `main`-Commit wird erstellt oder verändert.

## Architektur und Umfang

- Eine Option `mfpl_data`, autoload aus; vollständige serverseitige Validierung vor dem Ersetzen. Arrays bilden die manuelle Reihenfolge ab; stabile IDs bilden Zuordnungen ab.
- Zwei Ebenen werden beim Speichern erzwungen. Leistungen gehören zur zweiten Ebene. Keine CPTs/Taxonomien: für diesen abgegrenzten zentralen Editor wäre deren zusätzliche Oberfläche unnötig.
- Zeitplanung mit Grundpreis und versionierten Preiszeilen; UTC-Zeitpunkt beim Speichern aus WP-Zeitzone abgeleitet. Zur Ausgabe größter Zeitpunkt <= Serverzeit. Keine Hintergrundjobs, Transients oder eigenen Preis-Caches.
- Euro, zwei Dezimalstellen, Festpreis/ab/Anfrage; pro Preis ein optionaler Klartexthinweis. Keine Mehrwährung, Steuersysteme, Buchung, WooCommerce, Mehrsprachigkeitsverwaltung oder zusätzlichen Shortcode-Parameter.
- Öffentliche AJAX-Ausgabe umgeht gewöhnliche Seiten-Caches; JavaScript ist erforderlich. Der Server rendert und escaped sämtliche Benutzerdaten. Cache-/Browsergrenzen und Zeitzonenverhalten stehen in README.
- Editor nur `manage_options`, Speichern per POST/Nonce. Keine anonymen Schreibaktionen. Löschen des Plugins bewahrt Daten.
- Keine Bearbeitungssperre/Revisionen; Administratoren bearbeiten nacheinander. Keine automatische Migration und keine externe Abhängigkeit.

## Automatisiert verifiziert

23 eigenständige Domain-/Renderingprüfungen bestanden; PHP-Lint aller PHP-Dateien und Syntaxprüfung beider JavaScript-Dateien bestanden. Tests verwenden WordPress-Funktionsdoubles, keine echte WordPress-Laufzeit. Die Workflow-Datei erweitert die Prüfungen auf mehrere PHP-Versionen; deren Remote-Ergebnis separat prüfen.

## Noch erforderliche manuelle Abnahme in WordPress

- Aktivieren/deaktivieren, Editor ohne/mit Berechtigung öffnen; anonymer/falscher Nonce-Speicherversuch muss scheitern. Nur öffentliche Preisdaten über AJAX abrufbar.
- Damen/Herren/Kinder mit Unterkategorien anlegen; Leistungen, alle Preisarten und Hinweise speichern, neu laden und bearbeiten. Ungültiges Speichern darf bestehende Daten nicht ersetzen.
- Kategorien und Leistungen per Drag & Drop sowie ausschließlich per Tastatur sortieren; nach Neuladen Reihenfolge prüfen. Zuordnungen und blockiertes Löschen prüfen.
- Preise vor, genau zu und nach einem nahen Gültigkeitszeitpunkt prüfen; Seite offen lassen, Hintergrund/Zurückkehr, mehrere Shortcodes, Netzfehler und Retry prüfen.
- Einen echten Seiten-Cache/CDN nutzen: AJAX darf nicht gecacht werden; Zeitwechsel muss ohne Cron funktionieren. Antworten auf Cache-Header prüfen.
- 320px-Mobilansicht und Desktop mit dem echten Theme, Tastaturfokus, Fußnotenlinks, Screenreader-Status, lange Texte und identische Hinweise prüfen.
- JavaScript aus: erklärender Hinweis statt Preisbehauptung. AJAX blockieren: Fehlermeldung ohne alte Preise.

Diese Punkte wurden in der initialen lokalen Umsetzung mangels laufender WordPress-Testinstallation noch nicht ausgeführt. Kein produktiver Rollout und keine Änderung von `main`.
